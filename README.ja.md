# Timer OS · 时代系统

**Languages:** [English](README.md) · [简体中文](README.zh-CN.md) · 日本語 · [한국어](README.ko.md) · [Español](README.es.md)

> 過去は呼び出せる。現在は知覚できる。未来はスケジュールできる。

**Timer OS（时代系统）** は、アプリやファイルではなく、**時間・注意・コンテキスト・認知・行動** を中心に設計する実験的なオペレーティングシステムです。

「时代系统」という名称が示すのは単なる計時ではありません。連続する時間の中で、過去を整理し、現在の状態を理解し、未来の認知と行動をスケジュールすることを意味します。

このプロジェクトは一つの前提から始まります。物理空間が希少資源であるなら、**人間の注意は時間という資源の中で最も希少な部分** です。したがって有用なパーソナル AI は、質問に答えるだけでは不十分です。継続的にコンテキストを理解し、価値ある履歴を保持し、認知状態を維持し、人間の注意を本当に必要とする時だけ介入すべきです。

Timer OS は人間だけを対象にしていません。同じアーキテクチャは、継続的な感知、位置認識、自己モデルの維持、認知スケジューリング、行動計画を必要とする長時間稼働の具身エージェントやロボットにも適用できます。

## アーキテクチャ

Timer OS は四つの概念レイヤーで構成されます。

- **Body** — 現実世界への物理インターフェース。人間向けの最初の参照形態は分離型イヤホン + インテリジェント充電ケースです。具身ロボットでは、カメラ、マイク、IMU、測位システム、力/トルクセンサー、関節エンコーダー、モーターなどの物理 I/O を含みます。
- **External Brain** — 連続する経験を利用可能なコンテキストへ変換する認知・記憶サブシステム。
- **YIdui** — External Brain 内部の中核認知サブシステム。知識、認知状態、証拠に基づく自己モデルの更新を時間とともに維持します。
- **Timer OS Scheduler** — 履歴、現在状態、将来意図に基づいて、時間、注意、認知、行動を調整します。

スマートフォンは意図的に **表示・制御インターフェース** と位置付けられ、システムの中心には置かれません。

```text
現実世界
   ↓
Body（感知 / 位置 / エッジ実行 / バッファ / 接続）
   ↓
Timer Event Stream
   ↓
External Brain
   └── YIdui（認知状態 / 記憶 / 自己モデル更新）
   ↓
Timer Scheduler
   ↓
行動 / 将来の注意または運動資源の割り当て
```

## 認知スケジューリング

モデルのコンテキスト処理が基盤化するにつれ、Timer OS は **認知スケジューリング** をより上位のシステム問題として扱います。

- 何を高頻度で感知するべきか。
- いま、どの履歴を呼び出すべきか。
- どのモデル、どの推論深度を使うべきか。
- 認知やポリシーの衝突をいつ再評価すべきか。
- いつ行動を実行すべきか。
- いつ人間を割り込ませるべきか。
- 具身システムでは、どのセンサー、位置、モーター状態の変化が現在の計画を中断すべきか。

これにより、ハードリアルタイムな物理制御と、より遅い認知進化を分離します。安全クリティカルな制御ループは決定論的かつ境界付きのまま維持し、高レベル戦略のみを時間とともに評価・比較・更新します。

## 位置認識

具身システムにおける位置は、単一の GPS 座標ではなく、継続的に変化する状態ストリームです。Timer OS は、グローバル位置、屋内/ローカル測位、身体姿勢と向き、関節や四肢の位置、人や物体との相対位置、移動軌跡、現在位置推定の信頼度などを統合できます。

そのため、過去の位置、現在の姿勢、目標地点を認知スケジューリングや将来行動計画に利用できます。

## 具身自己モデル

Timer OS は、最初に人間が一度設定して終わるのではなく、現実世界の証拠によって継続的に修正される **Self Model（自己モデル）** を検討します。

自己モデルには次のような内容を含められます。

- 身体構造と現在の物理状態。
- 校正値と実測された能力限界。
- 学習済みタスク能力と失敗モード。
- 現在有効なモデル/戦略バージョン。
- 何を安全に実行できるかについての不確実性。

新しい観測結果が直ちに古い認知を上書きするべきではありません。複数のモデルや戦略を並存させ、証拠を蓄積し、テストし、最終的に保持・置換・環境別条件化することができます。

## 最初の製品原則：割り込みより先に入力

Timer OS はまず一方向の問題から始めます。

**現実 → Body → クラウド認知 → 持続可能な時間ストリーム**

最初のマイルストーンは、常に話しかけてくるアシスタントではありません。利用者への介入を最小化しながら、一日の高価値な情報を安定して再構成できるシステムです。

入力の信頼性が確認された後にのみ、Timer OS は **割り込むか、いつ割り込むか、どの方法で割り込むか** を判断します。

具身システムにも同じ順序を適用します。まず信頼できる状態取得と再構成を確立し、その後に高レベルの自律スケジューリングや自己更新戦略を段階的に有効化します。

## このリポジトリで公開するもの

このリポジトリには Timer OS の **公開スケルトン** のみを含めます。

- アーキテクチャ用語と境界。
- 連続時間ストリーム用の最小イベント契約。

## 非公開部分

次の内容は意図的に非公開です。

- Body のハードウェア設計とファームウェア。
- オーディオルーティングとシームレス録音チェーン。
- 話者/声紋認識実装。
- 位置融合・ローカライゼーションアルゴリズム。
- センサー/モーターのリアルタイムスケジューリング。
- エッジ判断とローカルバッファ戦略。
- YIdui の認知状態・自己モデル更新アルゴリズム。
- 知識、モデル、戦略の競合/更新機構。
- 戦略進化と検証ロジック。
- 注意/割り込みスケジューリング戦略。
- 本番クラウドのオーケストレーション、Prompt、スコアリング、ポリシーロジック。
- 独自データセット、ユーザーデータ、評価データ。

公開インターフェースは接続方法を示しますが、内部実装方法は公開しません。
