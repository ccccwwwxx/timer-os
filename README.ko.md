# Timer OS · 时代系统

**Languages:** [English](README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · 한국어 · [Español](README.es.md)

> 과거는 호출할 수 있고, 현재는 감지할 수 있으며, 미래는 스케줄할 수 있다.

**Timer OS(时代系统)** 는 앱과 파일이 아니라 **시간, 주의, 컨텍스트, 인지, 행동** 을 중심에 두는 실험적 운영체제입니다.

“时代系统”이라는 이름은 단순한 시간 측정을 뜻하지 않습니다. 연속되는 시간 속에서 과거를 조직하고, 현재 상태를 이해하며, 미래의 인지와 행동을 스케줄하는 시스템을 의미합니다.

이 프로젝트는 한 가지 기본 전제에서 출발합니다. 물리적 공간이 희소 자원이라면, **인간의 주의는 시간 자원 중 가장 희소한 부분** 입니다. 따라서 유용한 개인 AI는 질문에 답하는 데 그쳐서는 안 됩니다. 컨텍스트를 지속적으로 이해하고, 가치 있는 이력을 보존하며, 인지 상태를 유지하고, 인간의 주의가 실제로 필요한 순간을 판단해야 합니다.

Timer OS는 인간에게만 한정되지 않습니다. 동일한 아키텍처는 지속 감지, 위치 인식, 자기 모델 유지, 인지 스케줄링, 행동 계획이 필요한 장시간 동작의 embodied agent와 로봇에도 적용될 수 있습니다.

## 아키텍처

Timer OS는 네 개의 개념 계층으로 구성됩니다.

- **Body** — 현실 세계와 접촉하는 물리 인터페이스입니다. 인간용 첫 참조 형태는 분리형 이어버드 + 지능형 충전 케이스입니다. 로봇에서는 카메라, 마이크, IMU, 위치 시스템, 힘/토크 센서, 관절 인코더, 모터 및 기타 물리 I/O를 포함할 수 있습니다.
- **External Brain** — 연속적인 경험을 사용할 수 있는 컨텍스트로 변환하는 인지·기억 서브시스템입니다.
- **YIdui** — External Brain 내부의 핵심 인지 서브시스템으로, 지식과 인지 상태, 증거 기반 자기 모델 업데이트를 장기적으로 유지합니다.
- **Timer OS Scheduler** — 이력, 현재 상태, 미래 의도에 따라 시간, 주의, 인지, 행동을 조정합니다.

스마트폰은 시스템의 중심이 아니라 의도적으로 **표시/제어 인터페이스** 로 취급됩니다.

```text
현실 세계
   ↓
Body (감지 / 위치 / 엣지 실행 / 버퍼링 / 연결)
   ↓
Timer Event Stream
   ↓
External Brain
   └── YIdui (인지 상태 / 기억 / 자기 모델 업데이트)
   ↓
Timer Scheduler
   ↓
행동 / 미래 주의 또는 동작 자원 배분
```

## 인지 스케줄링

모델의 컨텍스트 처리가 점차 인프라가 되면, Timer OS는 **인지 스케줄링** 을 더 상위의 시스템 문제로 봅니다.

- 어떤 데이터를 고빈도로 감지해야 하는가;
- 지금 어떤 과거 정보를 호출해야 하는가;
- 어떤 모델과 어떤 추론 깊이를 사용할 것인가;
- 인지나 정책 충돌이 언제 재평가를 유발해야 하는가;
- 언제 행동을 실행해야 하는가;
- 언제 인간을 방해할 자격이 있는가;
- embodied system에서 어떤 센서, 위치 또는 모터 상태 변화가 현재 계획을 선점해야 하는가.

이 구조는 하드 리얼타임 물리 제어와 더 느린 인지 진화를 분리합니다. 안전 핵심 제어 루프는 결정론적이고 경계가 명확한 상태로 유지되며, 상위 전략만 지속적으로 평가·비교·갱신됩니다.

## 위치 인식

embodied system에서 위치는 하나의 GPS 좌표가 아니라 지속적으로 변화하는 상태 스트림입니다. Timer OS는 전역 위치, 실내/로컬 위치, 신체 자세와 방향, 관절 또는 사지 위치, 사람과 물체에 대한 상대 위치, 이동 궤적, 현재 위치 추정의 신뢰도를 결합할 수 있습니다.

따라서 과거 위치, 현재 자세, 목표 위치가 인지 스케줄링과 미래 행동 계획에 참여할 수 있습니다.

## embodied 자기 모델

Timer OS는 인간이 한 번 설정하고 끝내는 모델이 아니라, 실제 세계의 증거에 따라 계속 수정되는 **Self Model(자기 모델)** 을 탐구합니다.

자기 모델에는 다음이 포함될 수 있습니다.

- 신체 구조와 현재 물리 상태;
- 보정된 능력과 실제로 관찰된 능력 한계;
- 학습된 작업 역량과 실패 모드;
- 현재 활성화된 모델/전략 버전;
- 무엇을 안전하게 수행할 수 있는지에 대한 불확실성.

새로운 관측이 기존 인식을 즉시 덮어써서는 안 됩니다. 여러 모델이나 전략이 공존하면서 증거를 축적하고 테스트된 뒤, 최종적으로 유지·교체되거나 환경별 조건 전략으로 분화될 수 있습니다.

## 첫 번째 제품 원칙: 방해보다 입력이 먼저

Timer OS는 먼저 단방향 문제를 해결합니다.

**현실 → Body → 클라우드 인지 → 지속 가능한 시간 스트림**

첫 번째 마일스톤은 계속 말을 거는 비서가 아닙니다. 최소한의 사용자 개입으로 하루의 고가치 정보 흐름을 안정적으로 재구성하는 시스템입니다.

입력 신뢰성이 검증된 후에야 Timer OS는 **방해할지, 언제 방해할지, 어떤 방식으로 방해할지** 를 결정합니다.

embodied system도 동일한 순서를 따릅니다. 먼저 신뢰할 수 있는 상태 수집과 재구성을 확립한 뒤, 상위 자율 스케줄링과 자기 업데이트 전략을 단계적으로 활성화합니다.

## 이 저장소에서 공개하는 것

이 저장소에는 Timer OS의 **공개 스켈레톤** 만 포함됩니다.

- 아키텍처 용어와 경계;
- 연속 시간 스트림을 위한 최소 이벤트 계약;
- Body, Brain, Scheduler, 모델 Provider의 추상 인터페이스;
- DeepSeek Provider의 참조 경계;
- embodied agent, 위치 인식, 자기 모델의 상위 개념;
- 컴포넌트 연결 방식의 최소 예제.

목적은 독점 구현을 공개하지 않으면서 시스템 아키텍처를 논의 가능하고 상호 운용 가능하게 만드는 것입니다.

## 비공개 영역

다음 요소는 의도적으로 비공개로 유지됩니다.

- Body 하드웨어 설계와 펌웨어;
- 오디오 라우팅 / 끊김 없는 녹음 체인 구현;
- 화자/음성지문 인식 구현;
- 위치 융합 및 로컬라이제이션 알고리즘;
- 센서/모터 실시간 스케줄링 구현;
- 엣지 판단과 로컬 버퍼링 전략;
- YIdui 인지 상태 및 자기 모델 업데이트 알고리즘;
- 지식, 모델, 정책의 충돌/업데이트 메커니즘;
- 전략 진화와 검증 로직;
- 주의/인터럽트 스케줄링 전략;
- 운영 클라우드 오케스트레이션, Prompt, 점수화, 정책 로직;
- 독점 데이터셋, 사용자 데이터, 평가 데이터.

공개 인터페이스는 모듈 연결 방식을 설명할 수 있지만 내부 구현 방식은 공개하지 않습니다.

## DeepSeek

공개 스켈레톤은 모델 Provider에 중립적입니다. `DeepSeek`는 클라우드 추론 실험을 위한 첫 참조 Provider / 태그로 포함됩니다.

API Key는 이 저장소에 저장하지 않습니다. 공개 Provider는 인터페이스와 예시 경계만 포함합니다.
